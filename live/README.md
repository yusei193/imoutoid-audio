# NET RADIO — サーバー無しのネットラジオ（配信者ツール＋ゲスト＋聴取ページ）

PeerJS（WebRTC）だけで動く、サーバー不要のネットラジオ一式です。
配信者・ゲスト・リスナーはブラウザだけでつながります（音声はP2P、サイトは静的ファイルのみ）。
生放送中は**ライブチャット＆リアクション**も使えます（配信者のブラウザが中継ハブ。サーバー不要）。

```
net-radio/
├─ broadcaster.html   配信者コンソール（マイク／BGM／ジングル／ボイスチェンジャー／キューシート／ゲスト／DJフィルター／録音／タブ音声／おたより／入室ログ）
├─ guest.html         ゲスト用スタジオ（2人対談・マイク／ボイスチェンジャー）
├─ index.html         リスナー用ラジオページ（生放送 ＋ 24時間AIラジオ ＋ VJモード／おたより）
├─ vendor/peerjs.min.js  CDNが使えない時の予備
└─ preview-*.png      画面プレビュー
```

## 使い方

1. **配信者**：`broadcaster.html` を開く →「配信開始」→ マイクを許可
2. **リスナー**：`index.html?id=放送局ID` を開く → 再生ボタン（ID省略時は `kaeru-radio-live`）
3. **ゲスト**：配信者コンソールの「ゲスト招待リンクをコピー」を相手に送る → 相手が開いて「スタジオに参加する」

`https://` で置くのがおすすめです（`file://` でも動きますが、クリップボードやマイク許可が制限される場合があります）。
GitHub Pages などにそのまま置けます。

## 主な機能

### 配信者コンソール（broadcaster.html）
- **マイク**：ON/OFF（ミュート）／音量／デバイス選択／エコー抑制／ノイズ除去／AGC
- **🎛️ オーディオI/F・DJモード**：「トーク／マイク」と「オーディオI/F・DJライン入力」をワンタップで切替。DJモードでは `echoCancellation:false / noiseSuppression:false / autoGainControl:false / channelCount:{ideal:2} / sampleRate:{ideal:48000}` で入力を取り直し、ボイスチェンジャーは自動でバイパス（トークに戻すと元のエフェクトに復帰）。デバイスを抜き差しすると一覧が自動更新される
- **ステレオ入力メーター**：入力のL/Rリアルタイムレベル、ピーク値（dB）、0dBFS付近で点灯する**CLIPランプ**、入力ゲイン（0〜200%）。接続中の入力の実測値（44.1/48kHz・1ch/2ch・EC/NS/AGCのON/OFF）も表示
- **🎧 入力モニター**：オーディオI/Fの音を自分のヘッドホンで確認（初期OFF・ハウリング注意表示）。モニター音量と、対応ブラウザでは出力デバイス選択（`setSinkId`）
- **BGMデッキ（A/B 2デッキ）**：複数MP3のプレイリスト、再生・一時停止・次へ・シーク、音量、トーク時のダッキング（押している間だけ下がる）
- **🔗 URLから追加**：BGMデッキの「🔗 URL」／キューシートの「＋ URL」に音源URLを貼って追加（1行1曲・複数行まとめて可、最大20件）。CORS対応の直リンク（GitHub Pages・Dropbox等）はそのまま再生し、キューシートはlocalStorageに保存されて再読み込み後も残る。読み込めないURL（CORS非対応・共有ページのURL等）は理由を表示して追加しない
- **GoogleドライブのURL**：素の共有URLはGoogleの直リンク制限（別サイトからのアクセスを403で拒否）で再生できないため、同じパネルの「Google Drive APIキー」欄に無料のAPIキーを入れて「保存」すると `https://www.googleapis.com/drive/v3/files/<ID>?alt=media&key=…` に自動変換して再生する（キーはブラウザのlocalStorageにだけ保存。未設定なら案内を表示）
- **クロスフェード**：曲の終わり3.5秒前（0〜8秒で変更可）から次の曲を重ねて切替。キューシートの連続再生もBGMプレイリストも無音なし
- **ジングル／効果音（6種）**：内蔵シンセのポン出しSE（OPジングル・ピンポン・ブブー・拍手・**Air Horn**・**スクラッチ**）。外部ファイル不要で即鳴り、リスナーとモニターの両方に出る
- **🎛️ DJ FILTER**：-100〜0〜+100 の1本のノブ。左はローパス（こもり音）、右はハイパス（低音カット）、0はバイパス。`BiquadFilterNode`（LPF＋HPF直列）をバス（マイク・BGM・SE・タブ音声）に入れるので、リスナー・モニター・録音のすべてに掛かる。RESETボタン付き
- **🎙️ 配信をそのまま録音**：リスナーへ送っているミックス音声（`MediaStreamAudioDestinationNode` のストリーム）を `MediaRecorder` でそのまま録音。録音開始／停止、経過時間表示、試聴プレイヤー、`.webm`（対応に応じて `.ogg` / `.m4a`）でのダウンロード付き。配信開始後に使える
- **📺 PCタブ音声取り込み**：PCのChrome / Edgeで「タブの音声も共有」ONにしてYouTube等のタブを選ぶと、その音をBGMとしてミキサーに取り込む（`getDisplayMedia`、映像トラックは即停止）。専用音量スライダー（p^2.5カーブ）と停止ボタン付きで、DJフィルター・リミッター・録音・モニターにも乗る。音声なしで共有したときは「タブの音声も共有にチェックを入れて選び直してください」と案内。非対応環境（スマホ等）は押したときにPC限定の旨を表示
- **💌 おたより・リクエスト受信**：リスナーからのおたより（ラジオネーム・メッセージ・146曲からのリクエスト）が届くパネル。リクエスト曲は「＋ キューへ」1タップでキューシートに入る。送り主の 👤/🤖 バッジも付く
- **放送設定**：局ID、番組タイトル、DJ名、ひとことメモ（変更は接続中のリスナーへ即反映）、リスナー用URLコピー
- **🎛️ DJデッキ強化（第2弾）**：BGMデッキA/Bの音声バスに**3バンドEQ**（LOW `lowshelf` 250Hz / MID `peaking` 1kHz / HIGH `highshelf` 4kHz、各±12dB・RESET付き）、**HOT CUE A/B/C**（未設定で押すと現在位置を記憶、設定済みで押すとその位置へジャンプ、右クリック・長押し・「× クリア」で消去。曲を変えると自動でクリア）、**PITCH**（`playbackRate` 0.90〜1.10、0%=原速、RESET）、**BPM TAP**（直近8回のタップ間隔の平均からBPMを算出、RESET）
- **🎧 rekordbox風 2デッキDJミキサー（第3弾）**：BGMエリアを**独立した Deck A / Deck B**（PCは左右、スマホは縦積み）＋中央のミキサーに拡張。**横クロスフェーダー**（等パワー cos/sin カーブとバランスの2種、`A / 中央 / B` のワンタップ移動付き）、A/Bそれぞれの**チャンネルフェーダー・TRIM（±12dB）・3バンドEQ（±12dB＋RESET）・チャンネルFILTER**（左=LPF / 右=HPF）を持ち、音源はプレイリスト各行の `A` `B` ボタン・アーカイブ選択の `A` `B`・「LOAD先」セレクタ（AUTO/A/B）で好きなデッキにロードできる。**波形表示**は `decodeAudioData` で曲全体のピークを900分割してCanvasに描画し、再生位置のプレイヘッド・LOOP範囲・CUE点を重ねて表示。波形のクリック／ドラッグでシーク（デコードできない外部URLは下の位置バーでシーク）。各デッキに**PLAY/PAUSE**・**CUE**（停止中/再生中に押すとCUE点へ戻って待機、長押し・右クリックで現在位置にCUE点を更新）・**ヘッドホンCUE（PFL）**（プリフェーダーで分岐し、リスナーへ送るミックスには入らずモニター出力だけで聴ける）・**HOT CUE A/B/C/D**・**PITCH ±10%＋PITCH BEND（押している間 ±3%）**・**BPM TAP／波形からの簡易BPM推定**・**LOOP（IN/OUT手動・2s/4s/8sクイック・EXIT）**を搭載。自動連続進行やキューシートの「▶ 実行」ではA/B交互にロードし、クロスフェーダーも自動で目標デッキ側へ動かして無音の切れ目を作らない。トークのダッキング・マスターリミッター・録音・セットリスト自動記録は両デッキのミックスにそのまま掛かる
- **🗂 パネル折りたたみ／⌨ キーボードショートカット（第2弾）**：各パネルのヘッダーをタップで折りたたみ・展開（開閉状態を `localStorage` に保存）、上部に「すべて開く / すべて閉じる」。PCでは `M`=マイクON/OFF、`T`=トーク（BGM下げ）切替、`1`〜`6`=効果音パッド、`Space`=BGM再生/一時停止（入力欄フォーカス中は無効）。⌨ キーで一覧を表示
- **🔊 おたより・チャットの読み上げ（第2弾）**：`window.speechSynthesis` で配信者の端末スピーカーだけに読み上げる。Web Audio のグラフを通らないため、リスナーへの配信音声（WebRTC）には絶対に混ざらない
- **📺 テロップ（第2弾）**：おたより・チャット各行の「📺 テロップ」ボタンで、その内容を PeerJS DataConnection 経由でリスナー画面の上部に電光掲示板風に流す（「📺 テロップ解除」で消す）。受信側は `textContent` だけで描画し、200文字に制限
- **🖼️ ジャケット画像（第2弾）**：画像ファイルまたは画像URLから設定。Canvasで最大320×320・JPEG品質0.75に圧縮してDataURLにし、接続中のリスナーへ送信。新規入室者にも接続時に自動送信
- **📝 セットリスト自動記録（第2弾）**：再生した曲名（BGM・キュー・URL・タブ音声）と開始時刻を自動で時刻付きリストに記録。「📋 コピー」で `HH:MM  曲名` の整形テキストをクリップボードへ、「クリア」で消去
- **🔔 自動ジングル（第2弾）**：キューシートの自動連続進行時に「OFF / 3曲ごと / 5曲ごと」でOPジングルを自動挿入
- **👥 リスナー入室ログ（人間 / AI・Bot判別）**：リスナーが接続すると 👤 人間 / 🤖 AI・Bot / ❔ 未判定 のバッジ付きで入室ログに並び、ヘッダーのLISTENERS欄に内訳（👤○ / 🤖○）を出す。判定は `navigator.webdriver`、自動化UA（HeadlessChrome / Playwright / Puppeteer等）、URLパラメータ（`?bot=1` / `?client=ai`）、実際の操作（再生タップ・クリック）の組み合わせ。証明ではなく目安（スプーフィング可能）
- **ゲスト（2人対談）**：招待リンク、接続状態、ゲスト音量、ミュート、切断、ゲストの声を聴く
- **キューシート（番組進行表）**：トーク／MP3／imoutoidアーカイブ／ジングルを並べ、↑↓で並べ替え、▶で実行、⏭で次のキューへ、自動連続進行、JSON書き出し／読み込み、localStorageに自動保存
- **💬 ライブチャット（リスナー反応）**：リスナー・ゲストの発言とリアクション（👏❤️🔥🎵）をリアルタイム表示。DJ発言はハイライトして全員へ配信、配信者の返信欄と「クリア」ボタン付き
- **配信回線の自動復帰**：シグナリング（PeerJS）の接続を12秒ごとに監視し、切れていたら同じ局IDで自動的に再登録する。30秒ごとに「自分の局IDに別ピアから繋ぐ」自己診断も行い、**登録は生きているのに応答できない状態（スリープ・回線切替の後など）**を検知したら再登録する（画面には局IDと登録状態を表示）
- **画面スリープ防止**：配信中は Wake Lock でPCの画面スリープを抑止（対応ブラウザのみ）。それでもPC本体がスリープすると配信は止まるので、長時間の放送はPCのスリープ設定を「なし」に

### ゲストスタジオ（guest.html）
- マイクON/OFF・音量・デバイス選択、自分の声を聴く（試し聞き）
- **音量は聴感カーブ**：マイク音量・ホスト音量とも 0〜100% を `p^2.5` でゲインに変換（マイクは100%超の持ち上げ分だけリニア）
- ボイスチェンジャー（配信者と同じプリセット）
- ホストの音声（ホストの声＋BGM＋SE）の再生・音量・ミュート
- 接続状態（待機中／通話中）、5秒ごとの自動再接続
- **💬 ライブチャット**：リスナーの反応を見ながらコメント送信（ゲストの発言もリスナー全員に届く）

### リスナーページ（index.html）
- ON AIR／OFF AIRランプ、番組タイトル・DJ・メモ、ゲスト出演中バッジ
- 再生／停止、音量、リアルタイム波形
- **音量スライダーは聴感カーブ**：0〜100% の位置を `p^2.5` でゲインに変換（10%≒-50dB / 25%≒-30dB / 50%≒-15dB / 75%≒-6dB / 100%=0dB、0%は完全無音）。低〜中音量域を細かく動かせるので「少し上げただけで大きくなりすぎる」ことがない。初期値は80%（-4.8dB）。AIラジオの `<audio>` は要素の音量を1に固定し、マスターの `GainNode` 1か所だけで調整（`MediaElementSource` と要素音量の二重掛けを解消）
- **接続の現在地を常時表示**：画面下の小さい行に `peer:open / conn:open / call:recv / ice:connected / trk:1 / turn:on / st:局ID` を出し続ける（生放送が詰まったときどこで止まっているか一目で分かる）
- **局IDの自動回り込み**：`?id=kaeru-radio` で開いても、配信者が `kaeru-radio-live` で登録していれば自動でそちらへ接続する（逆も同じ）。Googleサイトの埋め込みURLのIDが古くても放送が聴ける
- **応答なしの案内**：両方のIDが未登録・無応答のときは、画面下に「配信者に接続できません（応答なし）。配信者側でページを再読み込みしてください」と出して、黙って `conn:connecting` のまま固まらない（7秒ごとに自動で再試行）
- **24時間AIラジオ（AUTO-DJ）**：生放送がOFF AIRのとき、imoutoid音源146曲を時刻シードで選曲して連続再生。生放送が始まると自動で生放送へ、終わるとAIラジオへ戻る
- **AI DJ**：日本語音声合成で曲紹介。音楽を止めず、音量を30%（-10.5dB）まで下げて重ねる（ダッキング）。読み上げは音量スライダーを通らないため、曲と同じカーブから声の大きさ（`volGain` の1.6倍・最大100%）を作ってバランスを取る。音声合成が使えない環境では自動で曲だけ流れる
- **💬 LIVE CHAT**：波形とプレイヤーの下にチャットパネル。名前（localStorage保存・空なら「匿名リスナー」）、本文、ワンタップリアクション4種。生放送中だけ送信でき、OFF AIR中は「生放送が始まるとチャットに参加できます」と案内。途中参加でも直近20件の履歴を表示
- **📊 3つの表示モード（WAVE / SPECTRUM / RETRO VJ）**：波形Canvas上のボタンで切替。WAVEは従来の時間軸波形、SPECTRUMは低音→高音の棒グラフ、**RETRO VJ**は低音・中音・高音（`AnalyserNode` の周波数帯域）に反応するレトロPC／Winamp／8bitドット風のVJ表示（セグメントメーター、ドットマトリクス、走査線、高音域でグリッチ）
- **💌 おたより・曲リクエスト**：ラジオネーム（任意）・メッセージ・リクエスト曲（146曲から検索して選択）をDJへ送れるフォーム。生放送中だけ送信でき、送るとDJ側の「💌 おたより・リクエスト」パネルに届く
- **🎚️ 音質プリセット（第2弾）**：生放送・AIラジオの両方に `FLAT（原音）` / `BASS BOOST（低音強化）` / `CLEAR VOICE（声くっきり）` / `NIGHT MODE（DynamicsCompressorで深夜の音量を均一化）` をワンタップ適用。生放送は受信ストリームの `clone()` を WebAudio に通し、`<audio>` 側を無音にして二重再生を避ける
- **📖 放送中曲の解説＆NEXT表示（第2弾）**：再生中の曲名・シリーズ（音源1 / 音源2）と、imoutoid.net の該当ページ（作品一覧・本文・アーカイブTop）へのリンクを表示。AIラジオでは「NEXT: 次にかかる曲」も表示
- **🕒 選曲ムード切替（第2弾）**：AIラジオの自動選曲を `自動（時間帯）` / `朝` / `昼` / `夜チル` に手動で切り替えられる
- **🕰️ 毎正時の時報（第2弾）**：AIラジオ再生中、毎正時にWeb Audio合成の「ポポポーン♪」と AI IMOUTO の英語アナウンス（"It's 3 o'clock. You're listening to AI IMOUTO Radio."）を鳴らす。ON/OFFと「時報テスト」ボタン付き
- **🔔 自動ジングル（第2弾）**：AIラジオで「OFF / 3曲 / 5曲」ごとに合成ジングルを挿入
- **🌙 スリープタイマー（第2弾）**：OFF / 15分 / 30分 / 60分。残り時間をカウントダウンし、終了10秒前から音量を滑らかにフェードアウトして自動停止（生放送・AIラジオの両方）
- **★ お気に入り曲（第2弾）**：再生中の曲を `localStorage` に保存し、一覧から再生・コピー・削除ができる
- **📼 波形モードを5種に拡張（第2弾）**：`WAVE / SPECTRUM / RETRO VJ / CASSETTE / OSCILLO`。CASSETTEは回転するリールとテープ量・メーターが音に反応するレトロカセット、OSCILLOは蛍光グリーンのリアルタイムオシロスコープ
- **📺 テロップ表示（第2弾）**：配信者が送ったテロップを画面上部の電光掲示板風バーでスクロール表示（`textContent` のみでXSS対策）
- **🖼️ ジャケット表示（第2弾）**：配信者が設定したジャケット画像をダイヤルの下に表示

## ライブチャットの仕組み

```
リスナー/ゲスト ──{type:'chat', name, text} / {type:'react', name, emoji}──▶ 配信者
配信者（最新50件をメモリ保持） ─{type:'chat-msg', id, role, name, text, time}
                              ─{type:'react-msg', id, role, name, emoji, time}──▶ 全員
新規接続 ───────────────────◀{type:'chat-history', items}（直近20件）
```

- 中継は配信者だけ。チャット用のサーバーやアカウントは不要（既存の DataConnection を使う）
- 受信した名前・本文は `textContent` だけで描画（XSS対策）、本文200文字・名前24文字まで
- 同じ接続からの連投は10秒20件まで、送信側も350msの連打防止でガード

## おたより・リクエストの流れ

```
リスナー ──{type:'letter', name, text, track:{t,u}, client}──▶ 配信者
```

- リクエスト曲はリスナー画面が持つ146曲リストのURLだけを受け付ける（配信者が任意のURLを再生させられない）
- 届いたおたよりは配信者の「💌 おたより・リクエスト」パネルに並び、「＋ キューへ」でキューシートに1タップ追加
- 送信は1.5秒に1回まで、本文500文字・名前24文字まで

## テロップ・ジャケットの流れ（第2弾）

```
配信者 ──{type:'telop', text, id, t}──────────────▶ リスナー全員（画面上部の電光掲示板）
配信者 ──{type:'jacket', data:'data:image/jpeg;…'}──▶ リスナー全員（ダイヤル下の画像）
新規接続 ◀─ info（現在の telop / hasJacket）＋ jacket（設定済みなら接続直後にも送信）
```

- テロップ本文は200文字まで、受信側は `textContent` でのみ描画（HTMLは入らない）
- ジャケットは Canvas で最大320×320・JPEG品質0.75に圧縮してから送る（数百KBの写真でも数十KBに）

## 人間 / AI・Bot 判別のしくみ

```
リスナー ──hello（client情報付き）／{type:'client'}──▶ 配信者（入室ログ＆LISTENERS内訳）
```

- リスナー側の判定材料：`navigator.webdriver`（+3）、自動化UA（HeadlessChrome / Playwright / Puppeteer / Selenium 等、+3）、URLパラメータ（`?bot=1` / `?client=ai` 等、+3）。合計3以上で `ai_bot`、それ以外は `human`
- 操作シグナル（最初のクリック・タップ・キー入力、再生ボタン）も送り、配信者の入室ログに「操作済み / 未操作」として出る
- あくまで目安：判定はクライアント側の申告なので、偽装は可能（botが人間のふりをすることも、その逆も）

## 音声ルーティング（2人対談）

```
入力（マイク or オーディオI/F） → 入力ゲイン ─┬→ ボイスチェンジャー（DJモードではバイパス）→ micGain ─┐
                                              ├→ 入力メーター（L/R・CLIP）                            │
                                              └→ 入力モニター（任意・初期OFF）→ ヘッドホン            │
BGMデッキA/B ─────────────────────────────────────────────────────────────────────────────────────┤
ジングル/SE ──────────────────────────────────────────────────────────────────────────────┤
ゲストの声 ──────────────────────────────────────────────────────────────────────────┘
                                                                                       ↓
                                                                       バス → マスター → リミッターA
                                                                                       ├→ mixedStream（リスナー／ステレオOpus）
                                                                                       ├→ マスターVU（L/R）
                                                                                       └→ モニター

入力（マイク or オーディオI/F） → ボイスチェンジャー ─┬─ BGM ─┬─ SE → リミッターB → returnStream（ゲストへ）
                                                      （ゲストの声は入れない＝ハウリング防止）

ゲストの声 → ゲスト音量 → ミックス ／ 別途モニター（配信者の耳）
```

- ゲスト自身の声はゲストに返りません（自分の声が遅れて二重に聞こえるのを防ぐため）
- 配信者にはゲストの声が聞こえます（「ゲストの声を聴く」でON/OFF・音量調整）
- スピーカーだとハウリングするので、2人対談は**ヘッドホン推奨**
- **DJ・オーディオI/F**：入力モニターをONにしたままスピーカーで鳴らすとハウリングします。モニターはヘッドホンで使ってください（初期OFF）。DJモードのボイスチェンジャーは素の音を優先してバイパスされます
- **ステレオ**：入力デバイスがステレオ（2ch）で、リスナー側もChrome/Edge等のOpusステレオ対応ブラウザならL/Rがそのまま届きます。モノラルのUSBマイクや、ステレオ非対応の再生環境ではモノラルになります（入力メーターとリスナー側で確認できます）

## 音量カーブ（聴感補正）

スライダーの位置（0〜100%）をそのままゲインにすると、10% でも -20dB しか下がらず、少し上げただけで爆音になりやすい。そこで3ページとも次のカーブで変換している。

| スライダー位置 | 10% | 25% | 50% | 65% | 75% | 90% | 100% |
|---|---|---|---|---|---|---|---|
| ゲイン | 0.0032 | 0.031 | 0.177 | 0.34 | 0.49 | 0.77 | 1.0 |
| 相当する減衰量 | -50dB | -30dB | -15dB | -9.4dB | -6.2dB | -2.3dB | 0dB |

- 0% は完全無音（`p === 0` はゲイン 0）
- 初期値：リスナー 80%（-4.8dB）／配信者 BGM 65%（-9.4dB）・マスター 90%（-2.3dB）・マイク 100%（0dB）・入力モニター 70%（-7.7dB）・ゲスト 100%（0dB）
- マイク／ゲスト音量の 100% 超（150%まで）は、100% までは同じカーブ、超えた分はリニアに持ち上げる（150% = +3.5dB）
- 入力ゲイン（0〜200%）は音量ではなくレベル合わせ用のトリムなので、横の dB メーターと合わせてリニアのまま
- AI DJ の読み上げ（`speechSynthesis`）は WebAudio を通らないため、同じカーブから声の大きさを作って曲とのバランスを取る

## 注意点

- **ブラウザ**：Chrome / Edge / Safari の最新版を推奨。`http(s)` での利用が確実です
- **局IDは公開されます**：PeerJSの公開ブローカーに登録するため、IDを知っている人は誰でも聴取・ゲスト接続できます。内輪で使うときは推測されにくいIDに変えてください
- **ネットワーク（STUN / TURN）**：STUN（Google / Cloudflare / Nextcloud:443 / Metered）に加えて、**Metered の公開TURN（`global.relay.metered.ca`、80/443 の UDP・TCP・TLS）を標準で組み込んである**ので、モバイル回線のCGNATなどNATが厳しい環境でも音声が中継されます。クレデンシャルは3ページとも先頭の `TURN_CREDS` 1か所にあり、一時的に別のTURNを使うときは URL に `?turn=ホスト|ユーザー名|パスワード` を付けるだけで上書きできます（`turn:` を無効にしたいときは `TURN_CREDS` の username を空に）
  - 2026-11時点の実測：認証不要の公開TURN（Open Relay の共有クレデンシャル、PeerJSの無料TURN、bistri、hubl、anyfirewall）はすべて停止・DNS消失。稼働しているのはアカウント制のMeteredのみ。
  - 無料枠は 500MB/月（P2P直結のときは消費しない）。使い切るとTURN経由の接続だけが止まり、直結できる回線では引き続き再生できます。
- **ローカルMP3**：ブラウザの仕様で、再読み込み後はファイルを選び直す必要があります（進行表の並び・タイトル・メモは残ります）
- **AIラジオの音源**：`https://yusei193.github.io/imoutoid-audio/` のMP3を直接再生します（imoutoid-audio リポジトリ自体は変更していません）
- **AI DJ**：`speechSynthesis` の日本語音声を使います。音声が入っていない環境では曲紹介だけスキップされます
